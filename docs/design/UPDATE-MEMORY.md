# update-memory specification

## Problem and user outcomes

Important session conclusions and continuation state can disappear when work pauses or changes sessions. Preserve consequential accessible context selectively in authoritative project records without turning every interaction into documentation.

Users can capture discoveries during work, finish a task, prepare for a break or context reset, change sessions, or preserve context before thread settlement. The skill saves useful context; it does not perform the settlement.

## Procedure and completion

1. Discover the governing instructions, existing resource layout and applicable ownership/maintenance rules. Read only relevant records and accessible session evidence. Finish when intended destinations and update boundaries are clear.
2. Identify consequential changes using [context policy](CONTEXT.md). Exclude already recorded information, transient chatter, unsupported claims and secrets. Finish with a small justified update set, or a legitimate no-op.
3. Freshly read affected owners and make narrow edits. Update knowledge, decisions or task state at their authoritative destinations. Correct clearly superseded current wording while retaining useful provenance. Create a supporting record only when established ownership clearly permits it and useful content warrants it. If a necessary destination is ambiguous, report the gap and ask only when needed to proceed.
4. Create or update the established handoff only when continuation benefits, using `.agents/HANDOFF.md` as the default. Update an index only when navigation changed. Do not generate task-specific handoffs by default.
5. Check edited content against the evidence, verify references introduced by the edits, and report changed files, important saved context, gaps and any useful next action. For a no-op, give a concise reason; do not touch files merely to record invocation.

Concurrent conflicts follow the minimal procedure in [context policy](CONTEXT.md). Preserve uncontested useful updates where safe; report contested updates without claiming they were saved.

Follow the project's established distinction between durable conclusions, internal supporting artifacts and actual user deliverables. Put warranted new internal records in the appropriate existing agent-owned location instead of recreating a legacy catch-all output folder. Select a file or directory from actual content and project conventions; maintain concise discovery routes through established owners when needed without bulk-loading supporting artifacts. Respect independent existing owners in projects without `.agents/`. This maintenance does not authorize relocation of existing resources or a whole-directory audit, and already recorded context still produces no change.

## Boundaries

The skill operates within the existing architecture and maintenance authorization. It may create a useful record, but does not scaffold, migrate or redesign the workspace, invoke `agent-workspace`, or substantially change governing/safety meaning without approval.

It never automatically commits, pushes, changes Git configuration/tracking, closes or settles threads, starts/resets sessions, manages workers or runs operational backlogs. It does not depend on third-party handoff output, provider history APIs or exhaustive transcript recovery.

## Acceptance

Verify selective owner updates, useful new records, conditional handoffs, source/uncertainty preservation, safe conflicts and no-op behavior using the shared [validation scenarios](PORTABILITY-VALIDATION.md). Successful capture must leave a fresh reader able to find the relevant conclusion or next action without duplicating the complete conversation.
