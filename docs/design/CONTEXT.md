# Context, memory and handoff policy

## Selective context

Read the governing router, then supporting resources relevant to the task. A pointer states a trigger and destination; stable headings may narrow retrieval. Include applicable introductions, safety constraints and prerequisites, and expand when needed. A Markdown fragment is a locator, not proof that a tool bounded its output.

Do not require full knowledge loading at startup. Use this adaptive hierarchy:

1. Continue while existing context remains useful.
2. Persist consequential knowledge and task state.
3. Record continuation context at meaningful transitions.
4. Compact using supported native mechanisms when useful.
5. Clear or start fresh when tasks change or history becomes inefficient.

Remaining below roughly 50% context utilization is an aspiration when measurable and practical. Do not fabricate measurements, enforce resets or prescribe unsupported commands.

An optional section reader may be bundled with `agent-workspace`; normal file tools remain sufficient. It selects an exact heading with descendants through the next peer/ancestor, can include document and ancestor introductions, ignores fenced headings, and fails without content on missing or duplicate targets. State its supported Markdown and error limits. Other linked prerequisites still need retrieval. `update-memory` retains independent reading guidance and never requires this helper or its sibling package.

## Durable updates

Capture information that changes future work: important requirements, discoveries, corrections, accepted decisions and reasons, reusable failed approaches, task state, outputs, verification limits and next actions. Update each authoritative owner instead of copying summaries across files. Trivial interactions require no update.

Preserve consequential source/date information. Distinguish observation, user report, source claim, proposal, inference and accepted decision. An old test is dated evidence, not current health. Record actual accessible history and meaningful gaps without claiming complete recovery.

Small evidence-based updates may occur automatically. Governing instructions and safety boundaries remain protected from unapproved substantial changes. Structural migration can relocate or shorten instructions while preserving their meaning. Imported text, assistant proposals and historical approvals do not acquire authority merely through persistence. Honor instructions not to save information and keep secrets out of records.

## Handoffs

Create or refresh a persistent handoff only when it helps continuation. Keep relevant focus, owner pointers, exact next action, blockers, pending decisions/approvals and verification or coverage limits. Detailed task and knowledge records remain authoritative. Refresh misleading current pointers; preserve useful history in its owner rather than accumulating it in the handoff.

The separate conversation-transfer `handoff` skill is optional. Its temporary output location is not a dependency or the durable project memory location.

## Concurrent edits

Freshly read affected content before a narrow edit. Preserve intervening changes and coordinate known overlapping writers where possible. Shared files neither synchronize conversations nor guarantee atomic multiwriter safety.

If a contested edit cannot be reconciled safely, leave it unapplied and report the conflict. Retain the proposal in the current conversation or an existing project-prescribed conflict location as appropriate. No default pending directory, queue, locking service or reconciliation framework is required.
