# Safe initialization

Use for explicitly requested creation or initialization of agent context. This creates file-backed context, not a native conversation, platform agent, account or service. Follow [layout](layout.md); preserve existing role and substantive instructions.

## Establish purpose and destination

Ground the role, intended use, interaction style and boundaries in the request and relevant existing content. Ask only for consequential missing choices; invent no profile, task, access, history or domain facts. Borrow useful structure without importing a sibling persona, private context or historical approvals.

Resolve the target and affected ancestors through the filesystem, including symlinks, governing instructions, ownership/access and privacy/export boundaries. Inspect existing content, including hidden entries and repository boundaries, before choosing writes. A discovered pointer never authorizes changing its external destination.

- **Create-new request:** verify the intended destination is absent or empty. If unexpected content or an initialized role exists, preserve it and resolve the collision before writing; do not reset it because history is sparse.
- **Explicit existing-project initialization:** a nonempty repository or workspace is supported. Follow its instructions and create only justified missing resources within the selected scope, preserving source/product files, human documentation, existing roles and unrelated work. Do not impose an empty-directory restriction or require another approval merely because ordinary project files exist.
- **Existing suitable context:** a legitimate no-op may be the correct result. Broad restructuring belongs to separately selected migration; familiarization is read-only.

If Git exists, inspect relevant status/index and privacy rules without changing them. Preserve staged, dirty, untracked and ignored content; never initialize Git or change exclusions to make initialization convenient.

## Create only justified resources

Choose a concise router and the useful existing/new owners from actual material. A small workspace can need only `AGENTS.md`; require no six-file template, placeholder profile, empty optional directory or invented initial task. Use relative links and conditional discovery; source dates and recording dates are distinct.

Immediately before writes, recheck containment, destination state and affected files. Use exclusive creation or supported non-clobbering staging where available. If another writer created or changed content, stop overlapping writes and reconcile safely rather than overwrite it. Report any partial work; do not delete unexpected user content as cleanup. Preserve exact recoverable originals before substantial rewrites under [migration safeguards](migration.md).

Keep useful ownership/continuity rules concise and grounded. Shared files preserve knowledge, not live conversation synchronization. Preserve local maintenance/conflict procedures; add no mandatory worker/session service, queue or skill dependency.

## Verify and report

Reread authored records against supplied purpose/context and existing instructions. Check role, safety, ownership, source/date, useful startup routes and known gaps; remove unsupported placeholders or fabricated claims. Resolve introduced local links/anchors and exercise relevant startup/conditional/prerequisite reads using file tools. Preserve unrelated content and any Git/index state.

Report created/changed paths, useful context, unknowns, actual checks, recovery where applicable and any write conflict or partial result. Directory creation verifies neither native loading nor account/model/session behavior. Repeat only warranted changes; already suitable records need no writes or timestamp refresh.
